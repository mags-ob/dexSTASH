# How dexSTASH fits together

![dexSTASH architecture overview](architecture-overview.svg)

A request goes from the phone over HTTPS to your reverse proxy, then into the `dexstash` container on port 8000. Scan photos, Enhanced Search and picture lookups run in a second container, `dexstash-scanner`, at low priority, so pages and searches stay quick while a batch is being read. The two share the `data/` folder: the SQLite database (`dexstash.db`) and the downloaded data (`dexstash-catalog.db`), plus backups, photos, saved pictures and models. Backing up `data/` and `.env` backs up everything.

Every request to another site, from either container, goes through `app/sites.py`. It sends one User-Agent, `dexSTASH/<version> (+<repository>)`, and refuses any site that is switched off under Data sources › Price and picture sites, redirects included. TCGdex, TCGCSV, the European Central Bank's rates and PokéAPI are always on. The README's "Where your data comes from" lists every source and its terms.

## Every part

![dexSTASH detailed architecture](architecture-detailed.svg)

Solid boxes run on your server; dashed boxes are on the internet. Both diagrams are drawn by `tools/make_diagrams.py`, which reads the route, table and module counts from the code; run it again after changing the app's shape.

- **One web process.** The app runs one Uvicorn worker on purpose: the login lockout, the background threads and the job runner live in memory in that process. Each page gets its own database connection.
- **The web layer.** `app/main.py` creates the app, adds the middleware (the Origin check on forms, sessions, the proxy's visitor address and https, from `DEXSTASH_PROXY_IPS` only), serves `app/static/` and includes the routers. `app/routes/` has one module of pages per topic, each with its own `APIRouter`. `app/web.py` holds what several modules share: the Jinja environment and its filters, the sign-in checks, the background workers and helpers used by more than one page.
- **Feature modules** in `app/` do the work and take a database connection, so they're tested without the web layer.
- **Prices** come from one rule. The price update (and TCGCSV's and CardTrader's runs) write quotes to `price_quotes`; `prices.resolve(conn, card_id)` then works out each printing's price into `prices`: every source in `prices.SOURCES` counts, only for the printing it names (TCGplayer from TCGCSV, else TCGdex; CardTrader, its card listing on the one base printing; the price you typed and the PriceCharting price you typed for that printing, from `typed_prices`), each converted to US dollars at that moment's ECB rate (`fx.in_usd`, kept in the source's `paid`), and a source with no rate yet is left out. The row keeps the average, the range and the sources, and the same amounts in the install's currency with the rate used (`price_local`, `local_rate`; `prices.localize`). It runs whenever a quote or a typed price changes, and adds a history row (`price_snapshots`, with `local`) when the average moves. The nightly update fetches the rates first and `prices.localize_all` saves every row again at the new rate; changing the currency does the same in the background. Pages show the saved amount (`display.saved`), never converting as they draw.
- **Times** are stored one way, `2026-10-28T19:56:42Z` (UTC), through `app/clock.py`; pages show them in the time zone setting (`display.py`). A test fails when code writes a time another way.
- **Security headers.** Every HTML page is sent with a strict Content-Security-Policy (`main.CONTENT_POLICY`): scripts only from the app's own files, no inline scripts or `on…=` handlers. Small behaviours (confirm before sending, open and close a dialog, a picture that fails to load) are `data-` attributes handled by `app/static/js/actions.js`; a page's own data goes in a `<script type="application/json">` block.
- **Home Screen app** (`app/pwa.py`): the manifest, launch screens for each iPhone and iPad size (drawn by `tools/make_logo.py`) and a service worker (`/sw.js`) that only steps in when the server can't be reached, showing `/offline`.
- **CSV downloads** (`app/export.py`): your stash, a binder or your chases, in dexSTASH's columns or Collectr's, as UTF-8 with a byte order mark so spreadsheet apps read accents.
- **Find's card catalog** (`app/card_index.py`). `TCGdex.search_cards` answers from `index_cards` once every TCGdex set in that language is there; until then it asks TCGdex and starts a lowest-priority thread that fetches the missing sets, one GraphQL request a second. Names and artists are matched through an FTS5 trigram index (`index_names`, made in code when SQLite has it), so any part of a name matches as TCGdex's own filter does. Find prices cards nobody keeps from TCGCSV's stored product lists before asking TCGdex. `DEXSTASH_CARD_INDEX=0` turns it off.
- **Background jobs** (0.23.0, `jobs.py`): every long piece of work is a row in `jobs` and runs on its process's one runner, one job at a time: yours first (priority 0), then scheduled and automatic ones (1), oldest first. In the web app: price updates (`sync.PriceUpdater`: the full update, and the short run after adds and imports, `prices-short`, which quick adds share), the nightly update and its chores (`sync.Nightly` is the scheduler that adds them: backup, picture tidy and weekly recheck, history roll-up, Value over time; no catch-up after a restart), saving card pictures (`card_pictures.Checker`, woken by `poke_if_changed` when `kept_rev` moves: triggers count changes to the stash, chases and followed Pokémon), picture lookups (`card_pictures.LookupWorker`, a quick job that may run between a long job's steps), Find's catalog per language (`card_index.start`), import matching (`importer.Matcher`) and the jobs Data sources starts. Rows with `runs_in = 'scanner'` (fingerprinting, rechecks) run in the scanner by their kind (`Scanner.run`). Pages first: `main.pages_first` counts pages being answered (status polls in `main.POLLS` don't count) and a job's thread waits while any are, a few seconds at most each time, before each step (`Job.progress`) and each download (`sites.client`'s request hook); download pools inside a job wait too (`jobs.pool`). A restart stops every job that was running or waiting ("Stopped by a restart"; `startup._stop_left_over`, an import becomes `stopped` with a Start matching again button); only scans carry on. The nightly update asks TCGdex only about cards TCGCSV doesn't price or with no picture, and about every kept card once a week (`sync.tcgdex_due`), and works each card's prices out once, at its end. Not jobs: reading scan photos and comparing pictures (`scans.Worker`, `scans.PictureWorker`, as before), the scanning-off followed pictures (`scanning.LightWork`), and small page helpers (a set's TCGCSV read for sorting by value).
- **The scanner container** (`python -m app.scan_worker`) checks every 2 seconds whether anything in the database changed (`PRAGMA data_version`), and only then looks for work and leaves a heartbeat in `app_meta`, which Data sources shows. It reads photos with RapidOCR, runs Enhanced Search with the CLIP picture model through ONNX Runtime, and does picture lookups and fingerprinting. The photo reader and the model never run at the same time and unload when idle. `DEXSTASH_SCANNER` picks where it runs: `separate` (this container, with the `scanner` Compose profile), `inside` (a child process of the app at the lowest priority, started again if it stops, refused under 1.5 GB of memory; `app/scanning.py`) or `off` (no photo reading; followed Pokémon's pictures are looked up on one lowest-priority thread of the app). Left unset, `app_meta` 'scanning' decides between `off` (the default) and `inside`, set by the Scanning switch in Data sources (`web.set_scanning` swaps the child and lookups without a restart); the Scan tab only shows while scanning is on.
- **The database** is SQLite in WAL mode. `app/schema.sql` is the starting point; each later change is a numbered `_step_N` in `app/db.py`, run once in order, each all or nothing. The app backs the database up before running new steps, and an older version refuses to open a database a newer one has changed. Since 0.15.2 (step 8) what's downloaded and the same for everyone (TCGdex replies, TCGCSV, CardTrader, the sprite colours; `app/catalog.sql`) is in `dexstash-catalog.db`, attached to every connection as `catalog`, so backups hold only the household's data and Data sources can rebuild it. Since 0.15.3 (step 9) every downloaded price is a row in `price_quotes` there, and `prices.resolve` picks the one each printing shows into `prices` (with its `origin`: tcgplayer, cardtrader, manual, pricecharting or printing; cardmarket from 0.17.1 to 0.19.2); the catalog also keeps every TCGdex card per language (`index_cards`, with an FTS5 trigram index of names) for Find (`card_index.py`). Step 10 (0.16.0) marks an install already in use as set up, so only new installs get the first-run wizard. Step 11 (0.17.0) gives each binder a page layout (4, 9 or 12 pockets) and an order for its pages (`binder_pages.py`). Step 12 (0.18.0): every source with a price for a printing counts. `prices.resolve` stores their average as `price` (what lists, sorting, worth and the `average` price history use), with `range_low`, `range_high` and the `sources` counted; a downloaded price far above the rest is left out (`prices.keep_close`), and what you typed always counts. Step 13 (0.19.0) saves each price in the install's currency too, with the rate used (`prices` and `price_snapshots`). Step 14 (0.19.0) rewrites every stored time in the one format (`clock.py`), times kept as seconds since 1970 included; a table made before keeps its old default time, and a trigger rewrites what it fills in. Step 15 (0.20.0) keeps each source price's own date and link, a daily exchange rate table (`fx_rates`), TCGCSV's products per printing (Poké Ball and Master Ball apart), and typed prices per printing (`typed_prices`); one list of sources (`prices.SOURCES`) drives the update, `resolve` and the history, a price is only ever counted for the printing it names (a CardTrader card listing for the one base printing), and `sync.refresh_sets` is the short run after an add or import. 0.20.1 (no new step): each run's summary goes in `price_runs` (`sync.record_run`; the short run's in app_meta), pages read stored prices only (`web._prices_for`, `web._browsed_prices`), `fx_rates` is filled daily and once from the ECB's history (`fx.backfill`), history points keep low/high/samples through `value.rollup`, `prices.localize_history` re-saves history at each day's rate on a currency change, and `prices.printing_states` backs Cards to review and the coverage line. Step 16 (0.21.0) indexes the stash by card and printing, and keeps a followed card's own price copy only when it isn't stored in `cards`. Step 17 (0.23.0) moves the scanner's `worker_jobs` into `jobs`.
- **Starting up** (0.22.0, `startup.py`, from `main.py`'s start-up hook; importing the app sets nothing up): settings and the activity log first; then, before the first page, the backup, the database steps and the quick after-upgrade tasks (`upgrades.py`: numbered, each run once and recorded in app_meta, all marked done on a new database); then, in the background, the slow tasks (pages say the upgrade is finishing) and scans left from before the restart. If the part before the first page fails, every address answers with a plain "The upgrade didn't finish" page naming the error and the backup to put back. Tidies that used to run at every start (prices of cards nobody keeps, loose Chinese pictures) run with the nightly chores. `tests/test_round22.py` upgrades the tables 0.11 made (`tests/fixtures/db-0.11.sql`) and checks they match a new database's.
- **Helpers**: `app/binder_pages.py` lays binders out as pages, and `app/celebrate.py` keeps the in-memory "You got it!" note for each person until their next page.
